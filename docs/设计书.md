# 墨序 小说辅助系统设计书

版本：0.8 设计草案

日期：2026年11月18日

软件名称：小说辅助系统

项目品牌：墨序（Moxu）

建议仓库名：`moxu-novel-assistant`

项目目录：`D:\work_space\py\moxu-novel-assistant`

墨序是一款面向小说作者的本地桌面写作软件。启动后先创建或选择书籍，再进入这本书的写作工作区。作者在软件内编写、保存章节，通过顶部工具栏把人物、事件、积分和自定义属性面板插入正文，并管理与正文关联的设定、账本、关系和时间轴。

建议采用 C++、Qt Widgets 和 SQLite，优先提供 Windows 版本。第一版围绕“在一本书内写作、方便插入设定、查得到历史、发现前后矛盾”完成闭环，并加入基础校对及可选AI写作辅助。主体程序保持轻量，离线模型单独安装。本轮交付产品与技术设计，不包含程序实现。

## 一 产品目标和使用边界

### 核心问题

| 作者遇到的问题 | 软件提供的能力 |
| --- | --- |
| 多本小说的正文和设定容易混在一起 | 启动书籍选择页、每本书独立工作区和数据文件 |
| 写人物面板时需要反复查资料、复制数值 | 顶部快捷插入、可编辑输出模板和指定节点快照 |
| 字词不顺或长篇正文难以逐字检查 | 选区润色、整书分段校对、逐项查看建议 |
| 获得300积分，后续消费记不清 | 收支流水、自动余额、逐笔来源和超支提示 |
| 人物境界、身份、能力前后不一致 | 属性变化事件、指定故事节点的角色快照 |
| 人物越来越多，关系容易混乱 | 自定义关系类型、自动关系图、关系变化历史 |
| 同一本书混合多种题材 | 可组合模板、自定义实体类别和字段 |
| 插叙、倒叙导致时间和章节对不上 | 故事发生顺序与章节叙述顺序分别管理 |
| 修改早期剧情后忘记调整后文 | 影响预览、后续重算、问题清单 |
| 伏笔忘记回收，道具重复使用 | 伏笔追踪、物品获得与消耗记录 |
| 改错、误删或电脑异常退出 | 持久修改记录、撤销、自动备份和恢复 |

### 首期假设

- 面向单人作者，一本书由一个进程写入；支持创建和切换多本书。
- 第一版面向 Windows 11 x64，中文界面。Windows 10、ARM64、macOS 和 Linux 另做兼容性验证，不默认承诺。
- 书籍管理、正文写作、设定与账本、模板插入及基础规则检查离线运行，无账户、服务器或联网激活要求；AI模型作为可选扩展，不影响普通写作。
- SQLite 随程序使用，作者无需安装数据库服务。
- 以作者主动录入的结构化事实为计算依据；未记录的事实显示为未知。
- 内置可日常使用的章节正文编辑器，支持自动保存、手动保存、历史版本和文本导出；专业出版排版、投稿和复杂文字处理不纳入首期。
- 可选择继续使用其他编辑器并导入TXT，但软件内写书是第一版主流程，外部编辑器不是必需条件。

这些假设用于形成可实施的第一版。后续调整时更新本设计，不把项目路径中的 `py` 当作语言限制。

### 不纳入第一版的能力

云同步、多人协作、移动端、AI自动续写整本书、任意脚本插件、分支宇宙自动合并和自动历史考据留待后续。第一版包含整书校对任务和选区润色入口，不承诺识别全部语义错误或保证无错字。首期支持“重生前”“重生后”等自定义阶段标签，但只维护一条明确排序的正史事实线。

软件可以检查已登记数值与规则，无法仅凭未标注的自然语言保证整部小说没有逻辑漏洞。

## 二 命名与定位

对外名称为“墨序 · 小说辅助系统”，界面和安装程序保留用户指定的“小说辅助系统”字样。“墨序”表达写作资料和故事秩序，英文代码名为 Moxu。

仓库为 [PurpleScorpion/moxu-novel-assistant](https://github.com/PurpleScorpion/moxu-novel-assistant)，应用程序名拟为 `Moxu.exe`。名称未做排他性查询。

## 三 作者的日常使用流程

1. 首次启动选择小说保存目录，可以使用程序所在目录下的“书籍”文件夹，也可以指定其他位置。以后直接进入书架。
2. 从书架新建或打开书籍，首先进入基础资料工作区。通过左侧导航切换页面，在右侧编辑书籍和人物、维护人物关系、查阅事件账本。
3. 点击“进入专注写作”打开章节编辑器。需要维护资料时可直接切回，切换前保存当前编辑内容。
4. 写到人物、积分或属性面板时，点击顶部“插入”，选择对象、故事节点和输出模板，预览后插入光标位置。
5. 写到奖励、消费等真实变化时，选择“记录事件并插入”，一起预览账本变化和正文文本，确认后保存。
6. 正文自动保存；需要阶段性留稿时使用手动保存或命名版本。
7. 遇到词句不顺时选中文字，使用“润色”；写完章节或全书后启动“检查错别字”，逐项决定是否采纳。
8. 查看历史节点，追溯人物属性、余额、关系和正文引用；修改前文后处理影响清单。
9. 切换书籍前保存正文并妥善结束后台任务，退出时按策略备份；成稿导出TXT或Markdown。

为了降低录入负担，常用动作提供快捷入口：“获得”“消耗”“转交”“状态变化”“建立关系”。表单默认沿用当前章节和最近使用的人物，支持键盘操作、复制上一条事件及批量补录。复制事件后需要重新确认，不能自动重复入账。

## 四 功能模块

### 书籍欢迎页与独立工作区

启动方式参考IDE的项目选择页：默认展示“新建书籍”“打开书籍”“最近书籍”，选择书籍后才展示正文、人物、账本等功能。欢迎页显示书名、封面、保存路径、最近编辑时间和置顶状态；不在未选书时展示没有归属的全局人物资料。

新建书籍需要书名、保存位置和题材配置；可直接选空白配置开始写。创建时生成新的书籍标识和数据库文件，再加入最近列表；同名文件已存在时要求另选位置，不覆盖原书。已有书籍通过 `.moxu` 文件打开，移动后的文件可以重新定位。

一个主窗口同一时刻编辑一本书。提供“切换书籍”“关闭书籍返回欢迎页”“打开文件位置”。从最近列表移除仅删除入口，不删除书籍；第一版不提供容易误触的书籍文件永久删除按钮。原文件及其系统复制件具有相同书籍标识时，提示选择使用哪一份；“另存为新书”通过完整快照复制并生成新标识，后续相互独立。

切换前先保存当前正文、草稿和光标位置；失败则停留当前书并展示原因，作者可另存正文应急副本。AI结果与旧书标识绑定，不得在切换后插入新书。断开的外部文件显示失效状态，不能直接创建同名空书冒充原数据。

最近列表保存在本机应用目录的 `library.sqlite`，保存路径、展示缓存及独立的个人模板库，不保存书籍正文。每本书的真实内容存于自己的 `.moxu` 文件；目录索引丢失后可重新打开书籍重建，个人模板可另行导出备份，避免一本书损坏影响其他书。

### 写作 Skill、大纲与 AI 写作

Skill 保存作者可复用的写作要求，每条包含标题和自由文本。全局 Skill 归当前 Windows 用户，跨书共享；本书 Skill 随书保存。两个范围可有同名规则，选择器分别列出。若两者都选中，提示模型优先遵循本书规则。

全局和本书 Skill 页面均提供单文件交换。导入时由作者选择目标范围，成功后打开新增条目。文件头和 Markdown 正文分别保存，AI 写作使用规则正文。导出默认命名为 `SKILL.md`，保留已有描述和扩展元数据，为自建规则生成文件头。作者可以将文件分享给其他人，由接收者选择自己的导入范围。

大纲单独管理。每条包含标题、剧情内容和适用范围，可关联全书或已有章节。作者平时可以离线整理剧情。调用 AI 时，大纲随写作任务作为剧情参考，勾选的 Skill 则进入写作规则。两者均支持逐条选择并在发送前查看。

0.3 的入口位于专注模式的「AI 写作」。默认使用选区润色，或使用光标前最多 3000 个字符续写。作者可调整实际发送的正文和任务，选择 DeepSeek、智谱 GLM 或本机兼容服务。请求异步执行，可取消。候选正文经作者采纳后写回原位置，并使用章节版本机制保存。此版本在运行期间按云服务分别保管密钥，退出即释放。

### 章节正文编辑与保存

管理书名、简介、题材标签、卷、章节、创作状态和章节排序。每章支持摘要、正文、备注及关联事件。进入专注写作后，左侧卷章树切换章节，中间编辑正文。规划支持查找替换、撤销重做、字数统计、段落缩进、字号和行距设置。保存章节位置时使用稳定标识，改名或调整顺序不会让引用丢失。

正文以UTF-8纯文本语义保存，显示样式属于编辑器设置；段落、插入引用和校对位置通过正文块及锚点元数据管理，不把内部对象标识写进导出的小说。无需支持Word级富文本即可实现可编辑的游戏人物面板。

正文停止输入约2秒后自动保存；持续输入时最长约10秒提交一次文本检查点，中文输入法候选上屏前不保存未完成组合文本。`Ctrl+S`立即保存并建立可回看的章节版本，切换章节、关闭书籍时也触发保存。状态栏区分“保存中”“已保存”和“保存失败”，显示最后成功时间。程序异常退出最多可能丢失尚未提交的输入，不能宣传零丢失。

自动保存更新当前正文和恢复检查点；章节历史采用增量或去重存储，定期建立完整快照，避免每2秒复制整章导致文件膨胀。阶段性命名版本、AI采纳前版本和事件联合提交版本保留明确记录，不因普通自动保存合并而消失。

首期提供按章或全书导出UTF-8 TXT和Markdown，预览卷章标题、分隔符及当前保存版本。对未刷新引用或未处理问题给出清单，作者可导出当前文本。TXT导入先预览编码和分章规则，再事务写入；不直接覆盖已有章节。外部重新导入按新稿处理，不静默合并覆盖原文。

章节可以引用外部文件路径并保存少量摘录；软件不直接修改外部文件。外部正文改变后，摘录锚点可能失效，界面显示“待核对”，由作者重新定位。

### 顶部快捷插入与自定义输出模板

顶部常驻“人物”“属性面板”“事件”“资源”“物品”“模板”入口。弹出面板支持搜索对象、选择故事节点、选择模板和预览，确认后插入正文光标处或替换选区；不必离开当前章节。未创建对象时可从面板进入简化创建流程。

| 工具栏动作 | 示例 | 是否修改故事事实 |
| --- | --- | --- |
| 插入人物名称或描述 | 林澈走入大殿 | 只建立正文引用，不创造出场事件 |
| 插入属性面板 | 姓名、等级、生命值、积分、技能 | 读取指定节点的属性快照 |
| 插入已有事件描述 | 完成任务，获得300积分 | 引用原事件，不再次入账 |
| 插入资源余额 | 剩余积分：100 | 只读取账户并登记余额声明 |
| 记录事件并插入 | 消耗80积分购买丹药，剩余100 | 新建事件与插入文本联合保存 |
| 插入自定义片段 | 系统提示、技能说明、章节固定片段 | 按模板字段读取或使用手工输入 |

题材配置模板定义“有哪些字段和规则”；输出模板定义“这些数据如何写进正文”，二者分别管理。输出模板可创建、复制、重命名、排序、预览和导入导出，支持本书模板与可复制的个人模板。修改个人模板不自动改变其他书的模板副本。

模板编辑器支持固定文本、字段选择器、字段顺序、前后缀、换行、分隔符、小数显示及空值处理。首期提供“字段有值才显示本行”和技能列表展开，不执行任意脚本。占位符内部绑定稳定字段标识，显示名称改变不会失效；导入到其他书时先映射字段和资源。

游戏属性面板模板示例，花括号内容由字段选择器插入：

```text
【人物面板】
姓名：{{人物.姓名}}
等级：{{人物.等级}}
生命：{{人物.当前生命}} / {{人物.生命上限}}
积分：{{账户.积分.余额}}
技能：{{人物.技能列表}}
```

作者可改成单行、方括号列表或自己的系统提示风格。同一人物在第3章与第30章插入面板，分别绑定当时故事节点。未知值显示预览提示，由作者选择留空、略去或输入字面文本，不能默认为0。人物姓名等可选当前导航名称或故事时点名称，预览中说明来源。

插入后保存可正常编辑的正文文本，同时保留模板版本、来源对象、故事节点、数据版本和渲染快照。积分及属性数字可自动建立正文声明。后续设定变更只标记“引用可能已过期”，刷新必须预览差异并由作者确认，不自动改写已写好的前文。

手工编辑引用内容时标记“已手工修改”，保留来源但停止安全自动替换；再次刷新需逐处确认，或解除绑定保留纯文本。复制面板复制的是文本和可选引用，不产生新收入；删除面板只删除正文引用，不删除底层事件。需要撤销“记录事件并插入”时提供独立的整组撤销入口，执行后续影响检查，不能把普通删字当成退回积分。

“记录事件并插入”先将当前正文保存到已知版本，再预览事件及待插入文本；最终提交时校验书籍和正文版本，在同一数据库事务中写入事件、效果、正文修订、锚点和编辑记录。失败全部回滚，事件成为待修改草稿；原正文继续保留。跨章节插入同一事件仍只计一次账。

### 微型写作辅助

提供三个常用按钮：“检查选区或本章”“检查整本书”“优化词句”。基础规则检查随主程序提供；中文语境纠错和选区润色使用可选AI扩展包。具体候选与依据见 [AI写作辅助可行性调查](AI写作辅助可行性调查.md)。

润色读取选中词句、有限相邻段落、本章摘要及相关人物在当前故事节点的设定，提供“保持原意”“更简洁”“更自然”等操作。默认不续写剧情、不添加事件、不改账本。词语替换展示多个候选，段落优化展示原文与建议的差异，由作者选择采纳。

人名、别名、地名、功法及用户自定义词加入本书词典。人名、数字、单位和系统面板作为保护内容；检测到建议修改这些内容时禁止一键采纳并显示冲突，由作者修改建议或返回原文处理。事实检查与AI润色独立，AI不能用自己生成的数值替代账本结果。

整书检查在后台按章、段和模型允许的token长度分块，保留块边界上下文，统一返回“章节、原文位置、问题、建议、原因”。界面显示完成量、失败量和待检查量，支持取消和断点续查；一百万字作品通过分批检查覆盖，不一次塞进模型上下文，也不承诺全书全局语义理解。

建议绑定书籍、章节修订、段落标识和原文摘要。作者继续编辑后，应用建议前核对对应文本和范围；无法唯一定位则标记失效并重查。每次采纳写入章节历史并可撤销；批量采纳仅处理已勾选、无重叠且来源仍匹配的项，按章原子提交。

默认离线运行，本地AI由插件中心按需安装，作者不需要装Python、命令行工具或模型服务。未安装模型、也未配置外部服务时，保留基础规则检查；语境润色提示选择安装离线插件或连接自己的外部AI。联网AI作为可选后端，用户明确启用后才发送选择的文本和上下文，不因本地模型失败自动转云端。

### 接入用户自己的外部AI

第一版增加“设置 → AI服务”，支持DeepSeek、智谱GLM的官方通用API，并预留自定义兼容接口配置。基础检查、离线插件和外部AI是三种可选方式；配置外部服务不需要安装千问模型，也不套用本地模型的内存和显卡门槛，只需满足主程序要求及网络条件。

根据2026年11月18日核实的官方文档，DeepSeek和智谱GLM的通用API均使用API Key认证。产品入口命名为“连接AI服务”，不是输入聊天账号密码后自动调用。用户在系统浏览器打开厂商官网，登录并创建密钥，再回到墨序填写；墨序不读取网页版Cookie、密码或已有聊天会话。[DeepSeek认证说明](https://api-docs.deepseek.com/api/deepseek-api/)、[智谱API快速开始](https://docs.bigmodel.cn/cn/api/introduction)

| 服务预设 | API基础地址 | 凭据与边界 |
| --- | --- | --- |
| DeepSeek官方 | `https://api.deepseek.com` | 用户自己的DeepSeek开放平台API Key |
| 智谱GLM官方 | `https://open.bigmodel.cn/api/paas/v4/` | 用户自己的智谱通用模型API Key，不能假设与编程套餐密钥通用 |
| 自定义兼容服务 | 用户明确填写的HTTPS地址 | 单独配置密钥、模型及能力，需要通过兼容性测试 |

DeepSeek和智谱均提供兼容OpenAI格式的接口，可通过原生HTTP请求接入，不要求作者安装Python SDK；兼容格式不代表模型参数、错误码及响应完全相同，应用需要厂商适配层。[DeepSeek调用指南](https://api-docs.deepseek.com/quick_start/agent_integrations/)、[智谱兼容接口](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)

用户流程为：选择服务商 → 点击“前往官网获取密钥” → 填入API Key → 选择或填写可用模型 → 测试连接 → 保存。预设服务自动填好接口地址，密钥输入后掩码显示；测试使用固定短文本，不发送书稿，并提示可能产生少量API用量。连接测试成功仅表示当时认证与模型调用可用，不代表永久有效。

模型可用列表在厂商支持时获取，否则使用标注更新时间的预设和手工填写；模型下线或权限不足时给出具体原因，不自动换成其他收费模型。聊天账号、会员、编程套餐和通用API的使用权限按厂商产品分别核对，不能承诺登录已有账号就免费使用。首次接入采用已核实的API Key路线；只有厂商正式提供适用于第三方桌面应用的授权登录后，才增加浏览器授权流程，不用模拟网页登录代替。

支持保存多个服务配置并指定校对、润色各自使用的服务与模型。每次任务明确显示当前来源、模型和发送范围；切换服务后重新确认对应书籍的外发许可。已有任务固定使用启动时的服务配置，不能执行到一半静默切换厂商。正文保护、差异预览、版本检查与撤销规则和离线AI相同，外部AI同样不能直接改账本。

密钥使用Windows凭据存储，普通配置只保存凭据引用；不写入书籍文件、模板、导出、备份或日志。支持删除连接和更换密钥；撤销厂商密钥提供官网入口。原生桌面程序直接连接用户选定的服务，不经墨序自建中转。自定义地址或预设域名改变时重新绑定凭据，不把原密钥自动发往新主机，也不向跨域重定向转发认证头。

调用前显示本次选区、相邻上下文和附带设定的范围；第一次使用联网服务、扩大到全书或更换服务商时明确确认。只授权润色一段不能上传整本书。网络调用本身会把这些内容发送给对应服务商，其数据处理遵循该服务商约定；本地软件不能宣称联网模式下正文始终不出电脑。

API费用由用户自己的厂商账户承担。提供最大输出量、单任务调用上限、整书检查范围和用量记录；有可信价格配置时展示带更新时间的费用估计，没有时明确显示未知并提供官方价格入口。实际费用以厂商账单为准，不能把本机估算当成硬性账户扣费上限。[DeepSeek计费说明](https://api-docs.deepseek.com/quick_start/pricing/)

对密钥失效、无余额、权限不足和参数错误给出对应处理入口，不盲目重试；可恢复的限流或临时错误采用有上限的延迟重试。请求已发出但结果不明时标记状态，避免无提示重复调用产生费用。取消停止后续请求，已提交的远程请求仍可能产生用量；流式残缺结果只保留为未完成预览，不自动替换正文。网络失败不影响保存，也不自动切换其他模型或服务。

### 插件中心与按需安装

AI能力按用户选择做成可安装插件。主程序默认不包含、不下载、不加载任何AI模型，保持正文写作、模板插入、关系图、账本及基础规则检查的原有行为。作者在欢迎页或书内“设置 → 插件中心”中安装需要的能力；不安装插件也可以完整使用基础软件。

首个计划插件为“千问离线写作助手”，用于经过验证的选词与短段润色；中文专用纠错可另作为“中文离线校对”插件提供。插件界面标注具体模型、版本、功能和运行要求，不能因为装了润色插件就声称拥有全部纠错能力。最终模型版本以原型结果为准，不永久绑定某个最小模型。

安装流程为：查看插件卡片 → 点击安装 → 自动检查兼容性和空间 → 下载所需文件 → 校验与安装 → 启动自检 → 显示已启用。安装动作即授权下载卡片所示的插件及依赖，不要求用户再执行安装命令或配置模型路径。若需要增加未展示的大型依赖，先更新大小与范围供用户决定。

插件卡片展示用途、版本、完整下载量、展开占用、最低与建议配置、离线运行说明及“安装”按钮。下载阶段显示进度、速度、暂停与取消；兼容性不满足时在下载前说明，网络中断或空间不足时保留原有功能并提供重试或更换目录。只有校验及自检成功才能显示“安装成功”。

安装后顶部“优化词句”或“语境校对”入口立即可用，首次运行可能显示模型加载进度。正常安装无需重启主程序；未使用AI功能时不常驻加载模型。首次安装需要网络，之后本地推理可以断网；另提供离线插件文件导入。

插件按本机当前用户安装，可供多本书共用；词典、检查任务和建议始终归各自书籍。插件中心提供启用、禁用、查看版本、更新和卸载。禁用或卸载前结束对应任务并释放模型；正文、人物、账本及已采纳修改保留。插件卸载不删除书籍，分享书籍也不强迫接收者安装同一插件。

第一版只支持项目发布并验证过的插件包，不开放任意第三方脚本。插件包含模型、分词资源、原生运行时和辅助进程，作者无需自行安装Python、Ollama或开发工具。管理器负责以下行为：

- 通过版本化清单声明插件标识、能力、主程序兼容范围、系统架构、CPU要求、文件大小、依赖和校验信息；下载源采用项目维护的静态发布目录，例如GitHub Releases，备用源须提供相同可信发布物。
- 使用内置可信公钥验证发布清单签名，并核对文件摘要；解包限制在插件专用暂存目录，拒绝越界路径。通过验证和推理自检后，原子切换到可用版本，不执行包内任意安装脚本。
- 中断后可恢复下载；失败或取消不改变已安装版本。升级先保留旧版，等待运行任务结束后切换；失败回到旧版，插件版本升级不自动重写已有正文或建议。
- 插件目录、下载缓存和已安装状态独立于书籍数据库。程序启动时核对状态，处理断电留下的半成品；共享依赖仅在没有其他插件引用时清理。

插件可安装不等于每台电脑都必然安装成功。验收要求是在受支持硬件、足够空间和可获取发布文件的条件下，从软件内一次点击完成正常流程；不满足条件时清楚说明，基础写作不受影响。

发布阶段需要实际产出可下载的插件包、签名清单和测试通过的版本，才能兑现“一键安装”。本设计没有部署下载源或签发插件，也不把官方模型仓库的页面直接当作已经可用的产品插件中心。

### 插件最低配置提示与运行保护

安装前必须展示“最低配置、推荐配置、本机检测结果”三列对照，并明确提示：“此插件会额外占用内存和处理器资源；配置不足时可能明显卡顿。请查看本机检测结果后安装。”提示直接放在安装页面，不能只藏在帮助文档或安装完成后才出现。

| 检查项目 | 安装前显示与判断 |
| --- | --- |
| 系统与处理器 | 支持的Windows版本、架构、CPU能力要求及本机匹配结果 |
| 总内存 | 经过测试的最低与推荐内存、本机实际总内存 |
| 当前可用内存 | 当前可用量、预计模型加载及运行峰值、需要为系统与编辑器保留的空间 |
| 磁盘空间 | 下载大小、安装峰值空间、安装后占用与目标磁盘剩余量；峰值包括暂存和更新时旧版本 |
| 显卡与显存 | CPU版明确显示“无需独立显卡”；GPU版分别显示支持要求和可用显存 |
| 可用功能与速度 | 对应配置允许的上下文长度、任务范围，以及同条件下实测的延迟参考 |

最低配置绑定具体插件版本、模型精度、推理后端和允许的最大任务规模。每个公开插件版本必须先填写并验证这些数值；未完成测试的版本不得在普通插件中心开放安装。调查中的“4核、8 GB参考机”和“2 GiB工作进程目标”仅为测试起点，不能直接作为最终最低配置宣传。

不满足最低系统、CPU、总内存或安装空间要求时，禁用安装按钮，说明具体差项；不提供忽略硬性限制后强行运行的入口。满足最低但低于推荐配置时，清楚标示“可运行，但可能较慢”。检测失败显示“无法确认”，允许重新检测，不能当作通过。临时可用内存不足时建议关闭其他应用后重试，软件不擅自关闭其他进程。

下载前、加载模型前及每次开始AI任务前重新检查资源。安装后的首次自检也受相同限制：下载完成时若内存已经不足，状态显示“已安装，等待资源检查”，不自动加载模型，也不误报已启用。插件更新需重新评估新版本要求，不因旧版可运行就自动升级启用更重模型。

运行保护包括：先保存当前正文；AI工作进程设置经过验证的内存预算与CPU用量限制；默认仅运行一个AI任务；限制线程数、上下文长度、批量大小和输出长度；整书检查逐块执行，不把整本小说载入模型。为系统和编辑器保留资源，不能只判断“模型文件能放进内存”。

主程序持续观察系统可用内存、内存提交余量和AI进程资源占用。资源接近阈值时停止派发新块，取消或释放当前模型；若超时不响应，终止AI工作进程并显示原因，不终止主程序。异常后不无限自动重启模型，不自动改用联网服务；保存任务进度，让作者稍后继续。安装阶段也限制解压缓冲和并行度，避免校验与解包本身耗尽资源。

这些机制用于降低卡顿与资源耗尽风险，不能承诺消除操作系统、驱动或硬件故障。发布验收必须包含模型冷启动、最大允许输入、整书校对和其他应用占用内存时的场景，确认保护机制先于资源失控触发，且正文仍可保存。

### 人物与通用资料

统一将可被引用的对象称为“资料对象”，包括人物、势力、地点、物品种类、独立道具、技能、功法、任务和用户自建类别。界面使用作者自定义的名称，不要求作者理解数据库术语。

人物卡包含名称、别名、简介、标签、所属分类及自定义字段，并提供属性、资源、关系、出场和历史页签。同名人物允许存在，选择时同时显示别名和简介，内部始终使用稳定标识关联。

资料归档不等于人物死亡。死亡、复活、失忆、改名等故事变化通过事件记录；归档仅控制资料列表是否默认展示。被引用的资料不能直接硬删除，避免断开历史来源。

### 自定义字段与题材模板

模板只是可修改的初始配置。作者可以添加类别、字段、分组、关系和资源；同一本书允许使用多种题材配置。

| 字段类型 | 示例 | 录入与校验 |
| --- | --- | --- |
| 短文本与长文本 | 外貌、人物动机 | 长度限制，可选必填 |
| 整数 | 等级、年龄设定值 | 最小值、最大值 |
| 定点小数 | 身高、负重 | 单位、固定小数位、范围 |
| 单选与多选 | 境界、阵营标签 | 自定义选项、可配置顺序 |
| 布尔值 | 是否觉醒 | 是、否；未填保持未知 |
| 日期或故事时间 | 出生日、入宗时间 | 标准日期或自定义显示标签 |
| 对象引用 | 师父、所属势力 | 限定目标类别，可跳转 |
| 资源余额展示 | 积分、灵石 | 读取账本，不重复手填余额 |

字段分为“资料描述”和“随剧情变化”两种。资料描述如创作备注只保留编辑历史；随剧情变化的字段如境界、姓名、生命状态必须绑定生效事件，才能还原过去。人物卡的当前称呼作为导航标签，故事中的改名另用时变字段记录。

首期支持类型、单位、分组、默认值、范围、必填、枚举及排序，不提供任意代码执行。第二阶段再增加受限公式字段与规则编辑器。

字段名称修改保持内部标识不变。已使用的字段只能停用或通过迁移转换，不能直接改类型、精度或删除已有枚举值。迁移前展示受影响记录、转换失败项并备份，失败不提交。默认值仅供新建时建议，不反向填补旧历史中的未知值。

| 初始模板 | 示例配置 |
| --- | --- |
| 系统文 | 等级、经验、积分账户、任务、奖励和兑换事件 |
| 都市文 | 职业、身份、组织、金钱账户和人际关系 |
| 历史文 | 官职、爵位、朝代时间标签、阵营与战争事件 |
| 修仙文 | 境界序列、灵根、功法、灵石、丹药和宗门 |
| 空白 | 基础人物、章节和事件，由作者自行扩展 |

模板导入采用映射预览，字段同名但单位或含义不同不能自动合并。模板版本保留来源信息，更新模板不会直接覆盖书内已有配置和数据。历史模板中的年号等内容为作者设定，首期不附带权威历史数据库。

### 资源账本与物品

每个资源账户由“拥有者、资源种类、账户名称”确定。同一人物可以拥有现金、银行存款、可用积分等多个账户。不同单位或资源不能直接相加，银两兑换铜钱需要显式记录两边金额和汇率说明。

收支支持获得、消耗、转入、转出、调整；开账余额也作为一条有来源的期初记录。未建立期初记录的账户保持“未初始化”，不能默认为0参与计算。新账户创建向导默认建议以0开账，由作者确认。

积分等允许作者配置是否可负数；不可为负的账户在新建超支事件时阻止确认，允许保存为草稿。修改旧事件引起后续超支时，采用第七节的受影响状态处理。

初始示例：

| 事件 | 章节 | 变动 | 余额 |
| --- | --- | ---: | ---: |
| 建立积分账户 | 第1章 | 0 | 0 |
| 完成新手任务 | 第1章 | +300 | 300 |
| 兑换功法 | 第2章 | -120 | 180 |
| 购买丹药 | 第3章 | -80 | 100 |
| 尝试兑换150积分的装备 | 第4章草稿 | -150 | 预计-50，不能确认 |

查看100积分时，可展开完整计算过程：`0 + 300 - 120 - 80 = 100`。不能只显示一个可随意覆盖的“当前积分”输入框。作者希望直接改成150时，软件生成带原因的 `+50` 调整事件供确认。

可堆叠物品按数量账户管理，例如丹药数量为整数；独立道具按唯一对象管理，例如“祖传青铜剑”。一次购买可以同时扣积分、增加丹药和更新任务状态，所有效果在一次事务中保存。

同种资源转交给另一角色时，来源扣除和目标增加必须同时成功；独立道具转交时更改持有人，不能同时属于两个人。掉落、销毁和无主状态均可表达。完整制作配方、耐久和多仓库管理留到后续。

### 关系编辑与自动关系图

作者定义关系名称、方向、颜色和允许的对象类型。师徒、雇佣等属于有向关系，朋友、夫妻等可设为对称关系。对称关系只存一条事实，显示双向含义，避免两边分别修改导致不一致。

关系支持建立、结束和状态变化，也可记录备注、章节及生效事件。亲密度等变化值作为关系属性保存。A将B视为朋友、B将A视为敌人时，使用有向关系；不强行合并为对称关系。

图由已有关系数据自动绘制并排列，不代表从正文中自动理解和抽取关系。支持拖动、缩放、搜索、选择中心人物、按类别筛选和保存布局。节点位置只是视图设置，移动节点不会改变故事关系。

首期提供确定性的圆形初始布局和可取消的力导向整理，自动排列保留锁定节点。边支持箭头、关系名称和多重连线。图默认展示中心人物的一到两层关系，初始限制约200个可见节点，超出时提示缩小范围。完整关系表不受这一视图限制。

选择历史故事节点时，只展示该节点有效的关系。关系区间采用开始包含、结束不包含的规则；同节点内以事件顺序区分先结束、后建立。绘图使用 Qt Graphics View，它提供交互式二维图元和缩放能力；布局算法由应用实现。[Qt Graphics View 文档](https://doc.qt.io/qt-6/graphicsview.html)

### 时间轴与章节对照

提供三种入口：全书事件时间轴、单个人物时间轴、按章节查看事件。支持按人物、地点、事件类型和资源筛选，点击事件查看前后状态。

必须分清三种顺序：

| 概念 | 含义 | 用途 |
| --- | --- | --- |
| 故事顺序 | 故事世界中实际发生的先后 | 计算余额、属性、关系和持有状态 |
| 叙述顺序 | 作者在第几章向读者讲述 | 管理倒叙、插叙和章节引用 |
| 编辑顺序 | 作者在现实中何时修改了什么 | 审计、比较修订和恢复 |

事件可以出现在多个章节，例如第2章发生的事在第10章回忆；它仍是一个事件，引用两次不会重复扣款。纯章节重排不会自动改变故事顺序。

第一版用作者可排序的故事节点和节点内事件序号确定全序；排序键不是公历时间。节点可显示“天启三年冬”“秘境第7天”等标签，无精确日期也可排序。公历日期作为可选字段；复杂历法换算留到后续。

发生顺序未定的内容保存为待编排草稿，不进入正式状态计算。同时发生的独立事件可共享时间标签，但仍保留稳定计算次序；若涉及同一资源账户，要求作者指定先后。

“查看本章状态”要求选定该章关联的故事节点，默认选择该章主场景节点。存在多个时段时显示节点选择器，不能把章节末尾简单当作唯一世界状态。首期不自动计算“读者到本章已知的信息集合”。

### 历史记录与撤销

修改记录展示现实保存时间、修改对象、修改原因、前后差异及关联章节。人物设定、字段配置、事件、关系、章节和规则变化均需留痕。

未保存的表单编辑支持普通撤销；已经保存的业务修改通过新修订恢复旧内容，不物理抹去历史。恢复某个旧事件修订需要重新计算后续效果，不能简单执行相反金额。

首期提供事件修订对比、资料编辑历史、最近操作撤销，以及整书备份恢复。任意编辑时刻的全书审计快照查询、多分支版本合并作为后续能力，不在首期界面承诺。

### 一致性检查

首期内置可解释的检查，每项问题都显示事实来源、触发规则、关联人物或账户、故事位置、章节和可执行的修正入口。

| 检查项 | 处理方式 |
| --- | --- |
| 格式错误、数值溢出、引用不存在 | 阻止提交，无法标记忽略 |
| 非负账户超支、未持有道具却转交 | 新事件不能确认；历史修改后标记后续冲突 |
| 配置为有序的境界异常倒退 | 提醒，可说明“受伤跌境”等理由 |
| 角色死亡后参加普通活动 | 提醒，可标记回忆、灵魂活动、复活等例外 |
| 事件日期与已确定顺序明显冲突 | 提醒作者核对，不自动改剧情 |
| 章节中的余额声明与计算结果不同 | 展示声明值、计算值和来源 |
| 伏笔超过计划回收章节 | 提醒，不判定为错误 |

余额声明是作者手动登记的“这一处正文写了100积分”，关联对象、字段或账户、故事节点和章节摘录。只有建立声明后才能进行准确比对；第一版不声称自动理解全文。

作者可以对软提醒登记例外原因。例外绑定规则版本和具体证据版本，相关事件变更后需要重新核对，不能永久屏蔽同类问题。硬性数据约束不能通过忽略解除；作者确需负余额时应显式修改账户规则并留痕。

### 伏笔与设定条目

支持世界规则、地点说明、背景资料、伏笔和约定事项。伏笔记录埋设章节、预计回收章节、实际回收事件和状态。规则如“传送阵冷却三天”首期可以先记录文本和人工检查项，后续再转为可计算规则。

## 五 桌面界面与交互

打开书籍后默认进入基础资料工作区，左侧导航驱动右侧详情。人物列表和编辑表单同页展示，创建、修改和保存均在页内完成。专注写作有独立入口，可从编辑器返回资料工作区。界面采用黑底、荧光绿重点色及数字雨装饰，正文区域保持纯色。标准对话框使用中文并随屏幕空间调整大小。

| 区域 | 展示内容 |
| --- | --- |
| 顶部 | 书籍切换、保存、撤销重做、人物与模板插入、事件与资源插入、校对、润色、导出 |
| 左侧 | 默认卷章树，可切换人物与其他功能列表 |
| 中间 | 默认正文编辑器，可切换表单、时间轴、账本或关系图 |
| 右侧 | 关联对象、模板预览、历史来源、AI建议差异 |
| 底部 | 字数、光标位置、保存状态、故事节点、检查进度与备份状态 |

进入历史节点后，全局明显标示“正在查看某节点”。新增事件默认填入这个节点，提交前再次展示位置；不让作者在历史视图中误以为修改的是最新状态。

事件编辑器采用“基本信息、变化内容、影响预览”三步，也允许熟练用户在一个面板内完成。任何多项变化只提供一个最终确认入口，避免扣款已保存但道具未保存。

正文保存、事件草稿保存和事件确认分别显示状态：正文已保存不代表其中描述的奖励已入账。事件草稿默认在停止输入约2秒后自动保存，正式业务状态在作者确认时事务提交。自动保存失败需持续提示，不能只闪过通知或继续显示已保存。

首期支持浅色和深色主题、字体大小、常用快捷键、125%至200%缩放以及中文输入法。关系不能只靠颜色区分，还要有文字和方向标记。

## 六 技术选型与发行方式

### 推荐方案

采用 C++20、Qt 6 Widgets、CMake 和 SQLite 原生接口。开发开始时选择并锁定可获得、兼容目标平台的 Qt 与编译器版本，记录 SQLite 实际版本和编译选项，不直接跟随最新版浮动。

| 方案 | 适合本项目的方面 | 主要取舍 | 结论 |
| --- | --- | --- | --- |
| C++ 与 Qt Widgets | 原生桌面控件，可定制关系图，可携带必要依赖 | 内存与构建管理要求较高，需要验证分发依赖 | 首选 |
| C# 与 WPF | Windows 界面和数据工具开发方便 | 自包含发布需要携带运行时，体积需实测 | 备选 |
| C++ 与直接 Win32 | 可精细控制依赖与体积 | 动态表单、布局、高分屏及复杂图形开发成本较高 | 不作为首期方案 |

C# 同样可以让用户免装 .NET：自包含发布会携带所需运行时，框架依赖发布则要求目标环境已有运行时。因此“免装环境”不由语言单独决定。[Microsoft .NET 发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)

选择 C++ 与 Qt 是对本项目控件需求、分发体积和后续可维护性的综合判断，并非未经实测就断言它一定比所有 C# 方案更小。

### 控制依赖

主程序使用 Qt Core、Gui、Widgets；启用应用内模型下载时增加 Qt Network及其必要依赖，全部计入主体体积。SQLite通过封装后的原生C接口访问；测试工具不随程序发行。关系图使用Graphics View，避免额外嵌入浏览器。图像导出先支持PNG。

正文编辑器以 `QPlainTextEdit` 为技术原型起点，该控件支持纯文本编辑、查找和撤销等能力；正文版本、持久锚点和模板引用由应用层实现，不能只靠控件临时状态。[Qt QPlainTextEdit 文档](https://doc.qt.io/qt-6/qplaintextedit.html)

AI运行时与模型不随基础包强制安装。计划由独立的本地辅助进程调用原生推理库，通过管道与主程序通信；不用HTTP服务器，不要求用户安装Python或Ollama。模型及运行时版本需要一起锁定，尤其验证MinGW主程序与AI工作进程的部署依赖。

SQLite 单独锁定版本，统一事务、备份与迁移接口，避免不同访问层同时维护同一事务。C++ 使用资源自动释放和检查过的数值操作，数据库连接不能被多个线程随意共享。

### 发行形式

优先验证免安装 ZIP 包：解压后运行 `Moxu.exe`，依赖库随包携带。建议先用 Qt 支持的匹配 MinGW 工具链验证该路线；实际所需编译器运行库也要随发行包完整部署。

同时规划普通安装包，用于创建快捷方式、文件关联和卸载。若采用 MSVC，安装包应按官方部署要求处理 VC++ 运行依赖，不能要求作者自己去搜索下载安装。Qt 的 `windeployqt` 可收集 Qt 依赖，但仍需检查额外依赖并在干净系统测试。[Qt Windows 部署说明](https://doc.qt.io/qt-6/windows-deployment.html)

“无需安装开发环境”不等于只交付一个孤立的 EXE。为满足小体积和易维护目标，首期接受 EXE 加依赖目录；单文件 EXE 不作为验收条件。

Qt 发行涉及具体模块和第三方组件的许可要求。计划采用动态链接，并在发布前核对实际依赖、附带许可说明和所需材料；最终开源或商业发行方式确定后落实对应方案。[Qt 许可说明](https://doc.qt.io/qt-6/licensing.html)

## 七 状态计算与历史模型

### 一个事实来源

会影响故事状态的事实全部附着于事件：获得积分、消耗道具、境界变化、关系建立和结束。人物卡、账本和关系图是这些事实的不同视图，不分别维护可独立修改的余额或关系副本。

资料简介、布局和创作备注可作为普通数据保存并记录编辑历史，无需把每次拖动图节点都变成故事事件。

### 事件与修订

事件拥有固定标识，每次修改追加不可变修订，旧修订保留。事件当前修订指针决定当前正史采用哪个版本；草稿独立保存，不改变该指针。删除已确认事件生成作废修订，支持后续恢复。

一个事件修订包含故事节点、节点内顺序、描述、参与者、资源变化、属性变化、关系变化和物品变化。章节引用通过稳定事件标识关联，修订不会产生重复记账。

编辑记录保存现实时间、递增提交序号、操作者本地标识、原因和涉及的修订标识。提交序号决定编辑先后，避免电脑时钟回拨造成顺序混乱。首期按单人本地应用设计，不将该记录宣称为防篡改审计。

### 计算规则

针对当前有效修订，按“故事节点顺序、节点内事件顺序”处理事件；同一个事件的资源效果先按账户合并，再原子应用。修订中对同一对象同一字段不能有相互冲突的多次赋值。

资源余额使用期初值加累计变化；状态字段在查询节点取最后一次有效赋值；关系和持有关系根据建立、结束事件确定。所有查询默认返回指定事件执行后的状态，也允许查看执行前状态。

精确数值以有符号64位整数和固定小数位表示。例如两位小数的12.34保存为1234。积分等整数精度为0。加减、换算及汇总都检查溢出，不能用浮点数计算余额。资源精度一旦产生流水就不能原地修改；转换须经过迁移。超出数值上限时提示作者选择更大计量单位，首期不提供无限精度数值。

物品数量、账户规则和字段类型同时参与校验。未知状态不会自动变成0或“否”。没有足够事实的检查结果为“信息不足”。

### 修改前文与冲突处理

假设最初奖励300积分，先花120、再花80，余额为100。作者把奖励改为150时，预览应列出第一笔消费后的30和第二笔消费后的-50，并定位第3章冲突。

提交前提供以下选择：

1. 返回修改，取消本次提交。
2. 连同后续事件一起修正，作为一组提交。
3. 保存前文修订，并将受影响后续事实标记为“待修正”。

第三种用于真实改稿，不能让历史数据无法保存。结构合法的事实保留，相关账户从首个规则冲突开始显示“存在冲突”，可展示计算值-50及原因，但不显示为正常可用余额。依赖该状态的后续确认操作被阻止，仍可继续保存草稿和修改无关资料。问题清单必须持续可见。

“待修正”不会悄悄排除原有消费，否则会让余额看似正确却丢失事实。软件始终明确区分草稿、已确认事实以及已确认但存在冲突的事实。修正后重算并自动清除已解决问题。

事件排序、作废、恢复及期初值改变走同一套影响预览。首期允许整书重算，确保正确性；性能需要时再按受影响账户和对象增量处理。

### 原子保存与缓存

一次用户确认必须在一个 SQLite 事务中写入事件修订、全部效果、当前指针、编辑记录和书籍修订号。失败时全部回滚；使用命令唯一标识避免双击或重试导致重复入账。界面只有在提交成功后才显示“已确认”。

影响预览绑定读取时的书籍修订号，保存前再次核对；若有其他编辑改变了依赖数据，重新预览，不能沿用过期结果。

当前状态与历史快照只是缓存，可由事实重建。缓存带事实修订号，版本不匹配时显示重算中，不提供旧余额冒充新结果。每隔一定事件数可建立计算快照；修改前文后只保留仍有效的快照。程序异常退出后能够通过有效修订重新构建。

## 八 SQLite 数据结构概要

一本书使用一个独立SQLite文件，扩展名拟为 `.moxu`，包含正文、设定、章节、事件、历史、输出模板、检查记录及小型头像。应用级 `library.sqlite` 仅保存最近书籍与个人模板库，不承担任何一本书的正文真值。打开已有书籍可修复缺失索引，跨库操作不声称具有同一个原子事务。

大附件与外部正文引用不默认导入，导出完整书籍备份时明确列出未包含的外部文件。AI模型保存在应用模型目录，可由多本书共用，不重复塞进每本书的数据库或备份。

以下为逻辑表设计，具体字段、DDL、索引和迁移脚本在实施前定稿并用实际 SQLite 验证。

| --- | --- |
| `book_meta` | 书籍标识、名称、格式版本、当前修订号 |
| `schema_migrations` | 数据库结构版本、迁移时间、校验摘要 |
| `entity_types`、`entities` | 自定义类别、资料对象、稳定标识及归档状态 |

| `foreshadows`、`notes` | 伏笔、设定条目和章节引用 |
| `assertions` | 正文声明的字段或余额、预期值、故事节点和摘录 |
| `validation_issues`、`issue_exceptions` | 可重建问题缓存、证据版本、软提醒例外理由 |
| `change_sets`、`change_items` | 提交序号、现实时间、修改原因及前后版本引用 |
| `state_snapshots` | 指定故事位置的计算缓存及来源修订号 |
| `graph_layouts` | 图视图、筛选条件、节点位置与锁定状态 |
| `assets` | 受大小限制的内嵌头像、媒体类型和内容摘要 |

应用级索引另记录 `installed_plugins`、插件版本、启用状态、安装位置和安装任务；插件文件的切换与索引提交使用可恢复流程，不能假设文件操作与SQLite写入天然处于同一事务。模型权重不写入书籍文件。

外部AI配置以应用级 `ai_service_profiles` 保存服务商、地址、模型配置和系统凭据引用，书籍仅记录所选配置标识与外发许可范围；分享或恢复书籍后重新选择本机服务。任务用量记录保存请求标识、已知token用量、失败或取消状态及价格版本，不保存认证头。

逻辑关系为：一本书包含多种资料对象；事件修订引用这些对象并附带多个效果；章节可引用多个事件；各视图从事件效果中计算状态。

数值和需要查询的关系使用类型化列及关联表，不把整个业务模型塞进一个不可约束的 JSON 字段。JSON 可用于草稿、布局配置及完整修订载荷，但金额事实仍由类型化效果表承担。

外键在每个连接启用，确保引用完整。事件修订号在事件内唯一；命令标识在全书唯一；对称关系端点规范化；同一独立道具不能在同一故事位置拥有两个持有人。前三类静态约束优先通过数据库约束保证，时间相关不变量由事务内领域校验保证。

首期索引围绕故事排序、事件当前修订、账户流水、人物参与事件、关系端点、章节引用和提交序号设计。中文搜索先支持名称、别名和标签的子串匹配；全文检索优化另行验证中文分词效果。

文本锚点以稳定段落标识加段内范围定位，范围在持久层统一用Unicode码点计数，与Qt内部UTF-16位置显式转换。编辑时移动未受影响的锚点，拆分或合并段落时保存映射；与修改区域相交或恢复旧章节版本的锚点重新核对，无法匹配时失效，不猜测跳到其他同文段落。应用建议前同时检查原文摘要，覆盖中文、emoji和组合字符场景。

正文保存递增章节修订，不因每次打字触发全书账本重算；故事事实修订另行编号。原有书籍修订号仍用于跨模块一致性校验，计算快照依赖事实修订号。联合事件与正文操作同时推进相关版本，AI任务绑定独立的文本、词典及事实输入版本。

## 九 本地存储与数据保护

### 数据位置

首次运行时，作者可以使用可执行文件旁的“书籍”目录，或选择自定义保存目录。确认前验证目录可写，书架支持随时修改。修改设置只影响以后创建的书籍，已有书籍继续按原路径打开。应用偏好和最近打开列表按当前 Windows 用户保存。

同一本书的第二个窗口或进程只读打开，显示占用说明。使用本地锁协调写入，并结合 SQLite 自身事务锁处理异常；不能因残留锁文件就强行破坏数据库锁。

### SQLite 使用策略

拟采用 WAL 模式、外键检查、合理的忙等待时间和 `synchronous=FULL`，优先保护作者已确认的数据。写入由单一队列串行处理，后台读取使用独立连接。

WAL 模式运行中可能存在 `.moxu-wal` 和 `.moxu-shm` 文件，不能把打开中的主文件单独复制当作完整备份。数据库放在本机磁盘；不支持把正在打开的书籍放在网络文件系统上多人写入。[SQLite WAL 文档](https://sqlite.org/wal.html)

网盘同步应同步应用导出的备份文件，而非实时同步正在使用的数据库及旁文件。程序正常关闭时执行适当检查点，但备份完整性不依赖“正常关闭一定成功”。

### 备份与恢复

- 有新提交时，默认每10分钟生成一次自动备份；正常退出时补一次。
- 数据库升级、批量导入、字段迁移及大规模历史重排前生成独立备份。
- 自动备份建议保留最近20份及最近7天的每日一份，重合备份不重复计数；手动和升级备份不自动删除。
- 只有新备份成功并校验后才执行保留策略；失败时保留已有备份并显示原因。
- 备份目标可配置到其他磁盘，同盘备份主要防误操作，不能保证磁盘损坏后恢复。

使用 SQLite Online Backup API 生成一致性快照，输出到临时目标文件；成功关闭并检查完整性后再命名为正式备份。备份功能利用的是 SQLite 提供的在线快照机制。[SQLite Backup API 文档](https://sqlite.org/backup.html)

恢复时先检查格式和结构版本，在新文件中打开并验证，再让作者选择作为副本使用或替换当前书籍；替换前另存现有文件。失败保留原文件和已有备份，不能只留下一半恢复的数据。

### 升级和异常处理

数据库迁移采用递增版本，迁移前备份，事务内修改并验证，失败回滚。旧版程序遇到更高数据库版本拒绝写入，不尝试猜测结构；提供使用新版打开或另选备份的说明。降级通过旧格式备份恢复，不承诺自动反向迁移。

磁盘满、路径只读、数据库忙、备份失败和文件损坏均需给出具体原因及保留数据的操作建议。崩溃恢复后检查草稿和未完成操作，已成功确认的命令不能重复执行。

首期数据库不额外加密，隐私依赖本机账户与文件权限。离线写作和离线AI均不上传正文；模型下载只获取模型文件。联网AI若启用，首次使用和范围扩大时明确展示发送内容及服务商，不与模型下载授权混用。访问密钥放入操作系统凭据存储，不写入书籍、导出文件或日志。

## 十 程序架构与代码边界

采用桌面主进程加按需启动的AI辅助进程，不运行本地HTTP服务。未安装AI包时只运行主程序。界面通过应用服务调用领域逻辑，领域逻辑通过存储接口访问SQLite；辅助进程只接收选定文本和设定摘要，不能直接写书籍数据库。

## 十一 开发阶段与交付标准

### 阶段零 技术原型

制作书籍欢迎页、正文输入与自动保存、自定义字段表单、模板插入、200节点关系图，以及SQLite事务和备份原型。打出Release发行包，在未安装Qt、开发工具或语言环境的Windows虚拟机中断网运行。

本阶段决定Qt版本、工具链、依赖清单和打包路线，测量包体积、启动时间、中文输入法及高分屏表现。按AI调查中的样本和指标测试候选模型，选择能用的离线纠错及润色方案。若小模型不达标，记录缺口并比较更大可选模型或另行启用的联网方案，不把入口已存在当作AI能力交付。

### 阶段一 书籍写作与状态账本

完成书籍选择与切换、卷章正文编辑、自动保存与版本恢复、TXT导入导出，以及资料类别、自定义字段、人物、资源账户、故事节点、事件修订和历史回放。

验收重点是正文保存恢复、多书隔离、300积分示例、未知期初值、定点小数、同一事件多效果原子保存和历史修改后超支。

### 阶段二 第一版功能闭环

完成顶部快捷插入、自定义输出模板与历史面板、事件与正文联合保存、自动关系图、时变关系、独立道具转交、时间轴、章节对照、一致性检查、伏笔、历史和备份恢复。完成基础规则校对、整书分块任务、建议采纳、插件中心、DeepSeek与智谱GLM外部API接入，以及经过原型验证的离线AI纠错和润色插件；默认不安装AI插件、不启用联网调用。

本阶段结束形成可试用MVP。书内写作、快捷模板、关系图、自定义配置、历史、时间轴和可实际使用的AI辅助均纳入第一版交付；作者可以选择不安装AI包。模型尚未达标时可先发写作预览版，但不得称完整需求已交付。

### 阶段三 发行质量

完善四类题材配置和人物面板模板、新手引导、键盘与高分屏、大书籍编辑和校对性能、迁移恢复及发行说明。分别在干净Windows环境验收基础包与离线AI包，验证无模型、无网络、模型损坏或内存不足时正文仍能正常保存。

### 后续增强

在第一版稳定后，再推进公式字段、可视化规则、复杂物品、更多图布局、读者知识视角、从正文抽取事件与设定、更多AI服务适配、分支剧情及跨平台。公式仅使用受限表达式，需明确依赖、循环检测、舍入及失败显示，不开放任意脚本。

| A52 | 使用无效密钥、错误产品类型密钥、无余额或无权限模型 | 准确报错，不循环重试、不自动换厂商或收费模型 |
| A53 | 测试连接、润色选区、再申请整书联网检查 | 测试不发书稿；选区限定上下文；整书外发需明确授权 |
| A54 | 修改接口主机、删除配置、导出或分享书籍 | 密钥不转发给新主机，不进入书籍或日志，删除本机凭据关联 |
| A55 | 远程超时、流中断或取消任务 | 保存正文正常，结果不明或不完整状态可查，不重复自动采纳 |
| A56 | 网络任务运行中切换服务或书籍 | 在途任务来源保持固定，结果只归原书原版本，不能串写 |

测试分为领域单元测试、真实SQLite集成测试、异常恢复、模型离线评估和桌面手工验收。金额、事件回放、原子性、正文锚点、联合保存、幂等和迁移必须自动化回归；输入法、布局、图交互、长章输入及干净系统启动必须实机确认。AI质量验收按调查文档执行，不用功能按钮可点击代替效果验证。

| 决策 | 本设计采用的方案 | 影响 |
| --- | --- | --- |
