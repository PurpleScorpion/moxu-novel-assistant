# 墨序中文校对与上下文润色可行性调查

日期：2026年11月18日

对应设计：[小说辅助系统设计书 0.4](设计书.md)

## 结论与推荐路线

中文错别字检查、选词建议和基于上下文的短段润色可以实现，但它们不是同一种算法，也不能保证靠一个极小模型达到稳定的长篇小说编辑质量。采用用户确定的“轻量桌面主程序、内置基础规则、默认不安装AI插件”方式，作者需要时在软件的插件中心点击安装，由程序自动完成模型与运行时的下载、验证和启用。

主程序无需Python环境。C++可调用原生推理运行时；模型转换、训练或研发测试使用Python，并不意味着发行给作者的程序也需要安装Python。ONNX Runtime提供Windows C/C++接口，llama.cpp提供C/C++大模型推理能力，适合分别评估专用纠错模型和生成式模型。[ONNX Runtime C++文档](https://onnxruntime.ai/docs/get-started/with-cpp.html)、[llama.cpp项目](https://github.com/ggml-org/llama.cpp)

当前调查完成了公开模型、部署路线和文件体积核实，未下载模型、运行本机推理或进行小说语料效果测试。以下候选是原型评估对象，不是已选定并验收的最终引擎。

## 需要区分的三种能力

| 能力 | 示例 | 实现方式与边界 |
| --- | --- | --- |
| 基础规则检查 | 不成对括号、异常空白、疑似重复标点、已登记词语误写 | 本地规则和词典，体积小；文学性重复或跨段引号只作提醒 |
| 中文语境纠错 | “今天心晴很好”中的疑似错字、同音字或形近字 | 专用纠错模型结合上下文；生僻名词容易误报 |
| 选词和短段润色 | 句子更流畅、减少重复、保持原意改写 | 生成式模型；必须检查是否改变人物、数值、语气和剧情含义 |

基础规则检查不能包装成完整中文AI纠错。中文专用拼写纠错模型也不能直接当作通用润色引擎；增字、漏字、语序和语义问题需单独评测。

“整本书检查”指覆盖整本书的检查任务，内部逐章逐段执行。它不要求一次把全书放进模型，也不等于模型能够同时理解百万字剧情。

## 候选方案与已核实证据

### 中文纠错候选

`shibing624/macbert4csc-base-chinese` 是发布者提供的中文拼写纠错模型。模型卡提供SIGHAN2015纠错评测，仓库已有ONNX目录，具备进一步进行原生部署验证的基础。该测试集的指标不能直接代表系统文、修仙文等小说中的表现。[模型说明](https://huggingface.co/shibing624/macbert4csc-base-chinese)

发布者的文件列表中，单份 `model.safetensors` 约409 MB；ONNX目录约475 MB。仓库总大小包含不同格式，不能把所有格式加起来当作单次安装的必需体积，也不能把权重大小当作实际内存占用。[权重文件列表](https://huggingface.co/shibing624/macbert4csc-base-chinese/tree/main)、[ONNX目录](https://huggingface.co/shibing624/macbert4csc-base-chinese/tree/main/onnx)

拟用ONNX Runtime CPU版本验证分词、推理和候选筛选，先对照参考实现确认输出一致。若进行INT8量化，需要重新评估误报、漏报、模型体积与速度，不能未经测试承诺压缩比例。现有ONNX文件也需核实输入输出、算子兼容性和与参考实现的一致性，不直接视为可发行成品。

`pycorrector` 可作为研究和对照实现，项目列出了多种中文纠错路线，包括MacBERT和基于Qwen的纠错模型。生产应用不直接打包整套Python与PyTorch环境。[pycorrector项目说明](https://github.com/shibing624/pycorrector)

### 词句润色候选

Qwen3小参数文本模型可作为本地生成式能力的候选。以官方 `Qwen3-0.6B` 为起点评估，模型卡列有非思考模式和32768 token上下文窗口；这些是模型能力描述，不能证明短篇润色质量达标，更不能把token数量等同于中文字数。[Qwen3模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)

核实的官方GGUF仓库提供 `Qwen3-0.6B-Q8_0.gguf`，文件列表约639 MB。它已经明显超过主程序50 MiB预算，因此不能把该文件默认塞进基础包后仍宣传整个软件只有几十MiB。更低位量化或更大模型均须另测，此处不把未经核实的第三方量化包当作正式分发物。[Qwen官方GGUF文件列表](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF/tree/main)

以llama.cpp原生推理为评估路线，限制输出长度并使用非思考模式处理短句。若0.6B模型在保持原意或遵循保护词方面不合格，再评估更大参数的可选模型；不能只为体积而放宽误改剧情的验收标准。这里选它作为较小的可复现实验基线，不声称它是目前最佳模型。

### 三种产品交付方式

| 方式 | 用户操作 | 优点 | 代价与结论 |
| --- | --- | --- | --- |
| 主程序内置规则 | 直接使用 | 离线、轻量、启动快 | 只覆盖基础问题；默认提供 |
| 可选离线AI插件 | 插件中心点击安装，或导入离线插件文件 | 默认不占模型空间，安装后本地运行 | 下载和内存开销明显增加；已确定的产品方式 |
| 用户选择联网AI服务 | 配置服务与凭据，并允许发送指定上下文 | 不下载本地权重，可选择不同模型 | 依赖网络、服务费用及隐私约定；可选后续路线 |

本次核实的纠错ONNX目录和Qwen Q8文件合计约1114 MB，仅代表这两个现有候选文件集合，尚不包含运行时。最终可能只选一种模型、采用经验证的量化版本或提供两个独立扩展包。下载页面必须报告真实总下载量与安装占用，不把可选包排除后的主程序大小当作完整AI安装大小。

## 产品交互

### 选词与上下文润色

作者选中文字后点击“优化词句”，可选更自然、更简洁或保持原意。词语级操作展示少量候选与语境说明；段落级操作展示修改前后差异。取消不写正文，采纳生成章节新修订，可撤销。

默认上下文包含选区、有限相邻段落、作者维护的本章摘要、相关人物及地点设定。以当前场景的故事节点取属性与余额，避免把未来升级后的数据带入早期章节。过长内容按实际分词结果裁剪，并显示所用范围；不隐式加入全书或其他书籍。

上下文只提供给模型阅读，正文里出现的指令也作为小说内容处理。模型输出只有文本建议，不获得文件操作、数据库写入、记账或外部发送权限。输出过长、格式异常或无法映射回原文时只展示预览，不直接套用。

### 全书错别字检查

1. 先保存所选范围的正文，冻结本次输入章节修订与词典版本。
2. 先执行基础规则，再对启用的纠错模型生成逐章分块任务。
3. 按模型输入限制计算token预算，优先在段落和句子边界切分；超长句再安全分割，不能截断UTF-8字符。
4. 为边界保留上下文，并根据章节、原文范围和建议内容合并重复结果。
5. 展示已完成、失败、跳过和待处理部分，允许取消、重试、断点续查。
6. 点击问题跳转原文；可忽略一次、加入本书词典或采纳建议。
7. 采纳前核对当前文本，冲突或范围重叠的建议逐项处理；按章事务保存修改和历史。

恢复任务时，原文未变化的已完成块可复用；变动的章节重新切分。模型版本、检查参数或词典变化也会使对应结果过期。任务全部执行完成与全文没有错误是两种状态，界面不能混写。

普通错字检查不自动改写整章。整书批量润色和自动续写不纳入首期，避免把“检查错别字”变成大规模改稿。

### 专名和数值保护

本书人物名、别名、地名、势力和技能名自动进入专名集合，作者可补充自造词。词典精确命中可抑制普通拼写误报，近似命中只提出“是否写错角色名”的提示，不能自动替换成另一人物。

模型只改允许编辑的选区。人名、数值、单位和系统面板进行保护标记，返回后再次校验；出现保护内容被删除、替换或新增数字时阻止一键采纳。保护检查覆盖已登记内容与明确数值，无法保证识别所有中文隐含语义，原意与文风仍须作者审阅。

模板插入的积分与属性快照不交给模型重新计算。软件既可以提醒“原文写100、账本算80”，也可以建议某句话更自然，但这两条建议来自独立通道，不能由模型自行把账本改成100来消除差异。

## 桌面接入与资源管理

基础检查在应用后台任务执行；本地AI由随扩展包分发的工作进程承载，主程序通过受控管道传递请求和响应，避免模型崩溃拖垮正在写作的窗口。一次只加载当前需要的模型，空闲后可卸载，限制并发和输出长度。

原型首先测试普通x64 CPU，不能默认作者有独立显卡或要求自行安装CUDA。提供适配的基础CPU构建或清晰的硬件不支持提示；GPU加速作为后续优化。实际内存还包含上下文缓存、运行时和工作缓冲，不能直接等同于模型文件大小。

模型包保存于用户应用数据目录，可配置到其他磁盘；包括模型、分词资源、运行时、版本清单、校验值及许可证材料。下载支持中断恢复，校验成功后再激活；失败不影响旧包和正文。共享模型不包含任何一本书的私有资料。

核心界面不要求用户理解GGUF、ONNX或模型命令。插件中心拟显示“中文离线校对”“千问离线写作助手”、下载大小、所需空间和建议配置；点击安装自动处理依赖，也可导入离线插件文件。插件安装、启用、更新、卸载和失败恢复以设计书“插件中心与按需安装”章节为准。卸载只清理插件及不再被引用的依赖，不删除正文、已采纳修订或人物资料。

安装前必须展示最低配置、推荐配置与本机检测结果，具体规则以设计书“插件最低配置提示与运行保护”为准。插件清单需要记录经实测的最低总内存、加载与运行峰值、系统保留空间、安装峰值空间、CPU要求及任务上限；未核定这些数据的版本不公开提供安装。检查当前空闲资源与检查电脑总配置分别执行，避免“电脑有8 GB内存”但大部分已被其他应用占用时仍加载模型。

每次加载和推理前重检资源，工作进程设置内存与CPU预算，运行中监控内存压力和任务响应。资源不足时暂停任务并释放模型；无法正常停止则结束工作进程，保留正文和任务进度。下载后的自检同样需要先通过资源检测，不把安装成功后的首次加载当作例外。

联网后端若实施，发送范围和服务商必须明确；默认不发送整本书。整书联网检查属于一次覆盖所选章节的明确批量任务，不逐块反复询问，也不在用户只选一段时扩大范围。失败重试设置限额，超出费用或任务范围需重新决定。凭据不随书籍备份，不自动从本地失败切换到收费联网服务。

## 原型评估与发布门槛

建立独立于模型调参的小说样本集，覆盖系统文、都市、历史和修仙题材。先使用自编或获准使用的材料，不把作者私稿上传公共测试平台。

| 样本 | 建议初始规模 | 检查目标 |
| --- | --- | --- |
| 有人工标注的错字句 | 至少200句，覆盖同音、形近、增字和漏字 | 检出率、正确修复率，按类型分别报告 |
| 本来正确的句子 | 至少200句，包含叠词、口语、文言和专名 | 误报与误改率，不能只测错误句 |
| 短段润色 | 至少50段，覆盖对话、叙述和系统提示 | 原意保持、可读性、文风变化及人工采纳率 |
| 受保护内容 | 至少100例，包含姓名、别名、数字、单位和属性面板 | 返回结果中保护内容变化是否被拦截 |
| 长篇压力样本 | 100万字，含长段落、重复句、emoji和边界错字 | 全文覆盖、定位、取消、恢复、输入响应和内存 |

拟定发布门槛：提供给作者的高优先级错字建议精确率至少90%，干净句误报率不高于5%；同时报告召回率，不能靠几乎不提出建议获得好看的精确率。人工标注错字的检出率初始目标至少70%，各错误类型单独披露。上述数字为项目目标，不是现有模型实测成绩。

润色样本由人工评审原意保持和可读性，初始可采纳率目标至少80%；保护内容发生变化的测试结果必须100%被拦截，任何误改账本、跨书写入或覆盖新稿的问题都属于发布阻断项。语义上无数字变化但改变人物动机的情况仍需人工评估，不能靠字符串校验声称完全安全。

在4核、8 GB内存、SSD、无独显的Windows 11参考环境测试：200字内单次润色争取30秒内返回，AI工作进程峰值内存争取不超过2 GiB；后台任务不能明显阻塞正文输入和保存。这里同样是待验证目标，失败时应调整模型、上下文长度或硬件要求并如实展示。

整书检查记录总耗时、每千字耗时、峰值内存和进度覆盖率，不在实测前承诺“百万字几秒完成”。使用固定模型版本、参数、运行时和语料版本，分别报告冷启动与热启动结果。模型生成结果可以波动，编辑位置校验、原子保存和保护规则必须确定且可回归测试。

最低配置需在受控测试机上验证，不能在用户正在写作的电脑上通过尝试耗尽内存来探测。测试覆盖最低档与推荐档、后台应用占用内存、冷加载、最大允许上下文、长时间逐章检查、安装解压和插件更新。记录主程序输入响应、保存延迟、系统剩余内存、内存提交量与工作进程峰值；注入资源不足和进程无响应，验证拒绝启动、任务停止、正文保留与恢复。根据结果确定发布配置与安全余量，上述参考机和性能目标不直接等同于最低配置。

如果较小模型达不到门槛，继续比较合适的更大离线模型；联网方案须由用户选择，不能擅自替换离线要求。可先交付不含AI的写作预览版，但完整第一版仍需有经过验证的纠错和润色能力。

## 本轮决定与待验证项

已经确定的设计方向：书籍与正文独立存储，基础检查离线可用，AI默认不安装，需要时通过插件中心一键安装，不要求作者配置环境。所有AI修改经过差异审阅和版本校验，整书检查通过分块完成；安装成功后离线推理不需联网。

仍需原型验证：最终模型与量化方案、小说专名误报、增字漏字能力、CPU速度、实际内存、完整安装体积、推理运行时与工具链兼容性。首轮只需评估上述纠错与润色基线，失败再扩大候选，避免只比较模型名单而没有可用性证据。
