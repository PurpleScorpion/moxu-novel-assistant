# 墨序 小说辅助系统

**[下载最新版 Windows 64 位便携包](https://github.com/PurpleScorpion/moxu-novel-assistant/raw/refs/heads/main/downloads/Moxu-win64.zip)**（当前为 <!-- moxu-version -->0.24.0<!-- /moxu-version -->）。解压整个 ZIP，双击其中的 `Moxu.exe` 即可使用。

面向小说作者的本地桌面写作软件。启动后创建或选择书籍，在书内编写和保存章节，通过顶部工具栏插入人物、事件、积分与自定义属性面板，同时管理设定、关系、资源收支和故事时间轴。

- 软件名称：小说辅助系统
- 项目品牌：墨序（Moxu）
- 建议 Git 仓库名：`moxu-novel-assistant`
- 项目位置：`D:\work_space\py\moxu-novel-assistant`
- 技术方案：C++、Qt Widgets、SQLite
- 首期平台：Windows 11 x64
- 当前版本：Windows 桌面写作预览版 <!-- moxu-version -->0.24.0<!-- /moxu-version -->

首次启动选择小说保存目录，默认使用程序旁的“书籍”文件夹。之后可在书架修改。每本书的 `.moxu` 文件就是一个 SQLite 数据库，保存章节正文、人物、事件账本和历史版本。在书架点书本右上角「⋯ → 打开本地目录」即可找到它。跨书共用的全局 Skill 单独保存在 `%LOCALAPPDATA%\Moxu\Moxu\skills.sqlite`。

打开书籍后，左侧可切换书籍概览、人物档案、人物关系和事件账本。右侧直接编辑书名、题材、简介和人物自定义属性。点击“进入专注写作”编写章节，顶部的“返回资料工作区”可切回。正文自动保存，在写作工具栏可以登记资源收支、插入人物属性面板、备份和导出。

在「人物关系」列表里点选一条记录，即可修改两端人物或关系名称。点「保存修改」或按 Ctrl+S 后，关系图也会更新。「删除关系」在当前页确认，只移除选中的这一条。

在专注写作的章节目录里，选中参照章节后点「＋ 新章节」，可在书末、当前章之前或之后插入。用「上移」「下移」调整选中章节，章序、AI 前文、时间轴和导出随之更新。如果移动会让已有的账本记录互相矛盾，例如先花掉尚未获得的灵石，软件会说明原因并保留原顺序。

专注写作页在章节序号旁实时显示本章字数。汉字、字母和数字各计一字，空白、标点和符号不计。

在「事件账本」点「记录事件」，可直接选章节并保存，保存或返回后继续查看原来的筛选结果和页码。勾选「同时追加到所选章末」会把事件文字写到该章末尾。在专注写作里记事件仍可插入当前光标或选区。

写作工具在正文旁高亮当前项。点「剧情大事」可在侧栏记录节点，点「属性面板 → 查看章节快照」可查看所选人物的状态，返回后继续编辑原面板。从写作返回资料工作区会恢复上次打开的栏目。新建资源的快捷入口沿用当前账本或写作侧栏，人物关系图也可在原栏目展开或收起。所有下拉列表从控件下方打开，靠近屏幕底部时可滚动选择。

章节正文、书籍概览、人物档案、全局 Skill、本书 Skill 和创作大纲在输入后约 1.8 秒自动保存。切换条目、离开页面或切到其他应用时会提前保存。按 Ctrl+S 或点击当前页面的保存按钮可立即保存，每次成功时都会显示带时间的确认提示。新建人物需要姓名，Skill 和大纲需要标题。

在专注写作中点击「历史版本」，从时间列表选择一份旧稿即可预览完整正文。连续自动保存时，同一章约每 5 分钟最多留一份旧稿。有待写入的正文改动时，手动保存或恢复不同版本会留存操作前的正文。

在「基础资料 → 书籍概览」可查看本书历史总份数和历史正文占用空间，点击「设置历史上限」可调整每章和全书各留多少份。新书和未配置的旧书默认每章 10 份、全书 100 份，历史正文共用 32 MiB。降低上限时按钮会显示即将移除的份数，点击应用后生效。任一份数设为 0 会暂停本书留档，章节正文继续自动保存。设置随书籍文件保存。

达到上限时优先保留近期版本，较久未改的章节可能只剩当前正文。单份旧稿超过 32 MiB 时跳过留档。0.12 之前已有的受保护历史也计入概览统计，可在「历史版本 → 整理全书旧版历史…」预览并确认将它们纳入本书额度。SQLite 会复用腾出的空间，书籍文件大小还包括当前正文、其他资料和数据库开销。

书架以封面展示已打开过的书和当前保存目录中的书籍，单击封面进入资料工作区。点击封面右上角「⋯ → 更换封面」可选择本地 PNG、JPG 或 BMP 图片，预览后点「保存封面」。图片随书籍保存，移动原图或备份书籍都能保留封面。要换回原样，点「恢复默认封面」再保存。菜单还可打开书籍所在目录，或在书架内输入完整书名，将选中的书籍文件移入回收站。同名书可通过文件路径区分。新书默认以书名命名文件，遇到同名文件，可修改文件名或选择其他目录。

专注写作的工具在正文右侧展开。「属性面板」在同一栏选择人物和模板，修改预览后插入原光标或选区。「记录事件」同时展示收支前后的余额，可选仅记账或同时插入正文。校验提示显示在表单内，输入内容会保留。点击「收起」可放弃本次操作，回到原来的写作位置。历史恢复、模板、备份和文本导出也在页内完成。

在专注写作中，点击章节目录右上角的「收起」可把宽度让给正文，点击正文标题左侧的「展开目录」可恢复。墨序会记住目录状态。左右侧栏可以分别收起，切换目录时会保留正在填写的事件。

在「基础资料 → 人物档案」左侧选人物，打开「章节快照」，选择章节即可查看章末状态。资源余额、持有道具、消耗品和技能／功法各有一张表，技能等级、冷却时间、剩余次数分别列出。在写作侧栏的「查看章节快照」也能查看这四张表。

在「基础资料 → 资源管理」可以新建、编辑或删除本书的数值资源、道具、消耗品和技能／功法。技能可预设初始等级、冷却与次数，登记习得时可以修改。编辑和删除仅作用于目录，此前的账本、人物资产和章末快照沿用原记录。账本的资源筛选包含所有类别和历史名称，同名跨类别的条目会标出类型。记录事件时也可以直接输入新道具、消耗品和技能名称。

在「事件账本」或专注写作的「记录事件」里点「新建资源」会打开独立页面。创建后回到原处并选中新资源，点「返回」可继续填写之前的事件。旧书已有的资源也能直接选择。在人物模板写 `{{灵石}}`，预览和插入正文时会取所选人物截至当前章末的灵石余额，尚无收支时显示 0。资源与人物自定义属性同名时优先取资源；与「姓名」等内置字段同名可写 `{{资源:姓名}}`。

「记录事件」可选资源收支、普通事件、获得道具、转赠道具，以及习得、提升、施展技能／功法。同一件具名道具首次获得后，可在持有人的「转赠道具」里选择接收人。技能按人物分别管理，等级可写“第三重”，冷却可写“三个时辰”。冷却是故事设定，由作者判断剧情里经过了多久。可用次数默认为不限，填 1 表示一次性，每次施展会扣除一次。补录早期章节时会校验后续章节的持有人和剩余次数。

血瓶、蓝瓶、一次性卷轴可按消耗品管理。在「记录事件」选择「获得消耗品」并输入名称和数量。以后可以从列表选择同名消耗品，登记获得、使用或转赠。转赠同时扣除赠予人的库存并增加接收人的库存，账本的变动与结余显示发起人的数量。模板里写 `{{血瓶.数量}}` 可取正文章节末该人物剩余的血瓶数，`{{消耗品}}` 会列出所有还有存量的消耗品。

属性模板还支持 `{{持有道具}}`、`{{已学技能}}`、`{{八九玄功.等级}}`、`{{八九玄功.冷却}}` 和 `{{八九玄功.剩余次数}}`。这些值同样跟随所选人物和章节。

在「基础资料 → 剧情大事」选择「＋ 新建大事」，选起始章节后点「保存节点」。例如「玄武门之变」可同时开设「宫门部署」「朝堂反应」两条支线，分别补记进展与结束。收束各条支线后，在主线保存结束节点。页面按章节展示整件大事的经过，专注写作工具栏也有「剧情大事」入口。

事件账本和时间轴都会展示剧情节点。账本可按人物姓名、资源和事件内容组合搜索，转赠可查赠予人和接收人，大事可查名称、支线名或经过。「章节倒序」优先展示后面章节的事件，同章按登记顺序倒排，也可切换为正序。每页 30 条，资源结余取该笔收支发生后的数值。

### 写作 Skill 与大纲

在资料侧栏打开「全局 Skill」或「本书 Skill」，为一条写作要求起名并填写内容。例如，全局规则可以约定“用动作表现情绪”，本书规则可以约定“师父对徒弟一律以姓氏相称”。全局规则保存在当前 Windows 用户的墨序数据目录 `skills.sqlite` 中。本书规则随 `.moxu` 文件保存和备份。

在任一 Skill 页面点「导入 SKILL.md…」，从页内文件树选择文件或粘贴路径，在「导入到」选择全局或本书，再点「确认导入」。错误会显示在当前表单，可以直接修正后重试。同名导入会新增一条规则。回到「AI 写作」即可勾选它。

选中规则，点「导出 SKILL.md…」并在原页选择保存位置。目标已存在时，可改名或勾选覆盖；更改路径会重置覆盖选择。删除 Skill 或大纲条目也在资料页内确认或取消。导出的文件包含当前规则的名称、描述和 Markdown 正文，墨序创建的中文标题可在再次导入时还原。支持 UTF-8 的 YAML 文件头和普通 Markdown。交换范围为单个文件；引用的附件需另行分享。[SKILL.md 格式说明](https://agentskills.io/specification)

「创作大纲」用于管理剧情。可在选中条目前插入新条目，也可以用「上移」「下移」调整阅读顺序，AI 写作里的大纲也采用这个顺序。每条大纲可属于全书或某一章，例如把“山门初遇，隐去师父身份”关联到第一章。大纲和 Skill 均支持直接编辑、保存和删除。

专注写作的章节目录显示序号，正文上方显示当前章及总章数。双击章节或点「改章名」即可就地修改标题。正文、历史和大纲继续关联到原章节。

### 设置和使用 AI

「AI 写作」的服务列表只显示一个「智谱 GLM」，默认使用 ZCode 兼容接口。首次使用可在「AI 配置」选择「智谱 GLM（ZCode 兼容）」，填写密钥并保存，再回到写作页选择「智谱 GLM」和 `GLM-5.2` 测试连接。要改用国内或国际通用接口，在「AI 配置」选中目标站点，点「保存并设为写作接口」。选择对所有书籍生效，各接口分别保留密钥和模型列表。[智谱国际站的 Anthropic 接口配置](https://docs.z.ai/devpack/tool/claude)

1. 在书架或「AI 写作」中打开「AI 配置」。智谱 GLM 提供「国内」「国际通用」和「ZCode 兼容」三个入口。也可选择 DeepSeek、本机兼容服务，或点「新增站点」填写兼容接口的基础地址。可直接使用预设模型，也可点「从站点读取模型」。支持模型列表接口的站点会自动补全列表，也可按每行一个标识编辑，保存后从下拉列表选择。实际调用权限取决于服务商账户。
2. 在本站点输入 API 密钥。默认仅在本次运行中使用，勾选「在此电脑记住密钥」后保存到当前用户的 Windows 凭据管理器。模型和站点设置对所有书籍可用。可以取消勾选再保存，移除持久保存的密钥。
3. 在专注写作中，选中文字后打开「AI 写作」，正文上下文只带入高亮选段。采纳润色稿时会替换进入页面时选定的范围。只有光标时上下文留空，可以直接布置写作任务、手动填写参考正文，或点「使用本章全文」。选择站点与模型后可点「测试连接」，只发送一条简短测试消息。云服务可能按用量计费。

   跨章续写时，点「引用上一章」带入最近一章的全文，更早的章节可以在左侧「前章摘要」中按需勾选。同一章的全文和摘要互斥，按原书顺序发送，可在「发送预览」中核对。只有主动选用的前文会随请求发出。

   AI 写作左侧的资料子项缩进显示，墨序会记住每个分组上次的收起或展开状态。

   在「基础资料 → 剧情摘要」可以选择全书任一章节，点「生成剧情摘要」生成或更新该章，也可点「一键生成缺失摘要」逐章补齐。批量生成会跳过已有摘要和不足 1000 字的章节。每次请求只发送所选章节的正文，新生成的摘要首行标明章序和章名。离开该栏目会停止后续请求，已经保存的摘要可在下次接着使用。

   剧情摘要的章节列表显示章序、章名、正文字数及摘要状态。生成摘要后再修改正文，会标为「正文已修改」，选中该行可重新生成。旧版摘要首次显示「旧摘要 · 待核对」。移动章节或改章名只更新软件生成的章节标题。

   AI 写作的「剧情摘要」页也可以为当前章或早前章节生成摘要。两个入口都按编辑器的正文字数判断，满 1000 字才可用 AI 生成。任意长度的章节均可手写摘要。摘要会自动保存到本书，也可以点击「保存摘要」。
4. 需要约束文风时勾选写作 Skill，需要剧情参考时勾选大纲，也可以都不选。在「发送预览」核对资料和上下文后发送。可查看生成进度或取消请求。
5. 候选正文下方可以连续输入修改意见，也可以先手改候选稿。点「发送修改意见」后输入框立即清空，发送失败或取消时会恢复本轮意见，方便重试。「修改记录」可查看已完成的意见，后续修改会带上本次对话的上下文。
6. 改整章时，在「写作要求」点「使用本章全文」。生成后点「对比本章修改」，在当前页查看带行号的原文删减和新稿增补。可以回到「候选正文」继续编辑，再对比一次。核对后点「覆盖本章全文」，在正文编辑器中可按 Ctrl+Z 撤销。候选稿、对比页和章节编辑器使用相同的字数口径。局部改稿仍可替换选区或插入光标处。修改对话只保留在本次 AI 写作页面内。

国内智谱和国际 Z.AI 使用独立站点。自定义接口支持 HTTPS，本机服务也可使用 `http://127.0.0.1:8080/v1` 等回环地址。[DeepSeek 接口文档](https://api-docs.deepseek.com/) · [智谱接口文档](https://docs.bigmodel.cn/cn/api/introduction) · [Z.AI 接口文档](https://docs.z.ai/guides/overview/quick-start)

预览版的资源以整数记录，首次登记前按零计算。属性面板插入时读取当前人物资料和截至本章的余额，之后保留为正文。正文版本可恢复。本版暂以章节顺序作为故事顺序，历史人物属性、独立剧情节点和内置模型插件中心仍在规划中。

### 开发与构建

开发构建使用 Qt 6.8.3（含 Qt Translations 中文语言包）、MinGW 13.1、CMake 和 Ninja。CMake 首次配置时获取并校验 yaml-cpp 0.8.0，静态链接到程序。中文控件翻译嵌入可执行文件。在开发机将配套 Qt、MinGW 和 Ninja 的 bin 目录加入 PATH 后执行：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=C:/Qt/6.8.3/mingw_64
cmake --build build
ctest --test-dir build --output-on-failure
```

### 发布 Windows 便携版

在 `CMakeLists.txt` 的 `project(Moxu VERSION …)` 中设置新版号，提交本次发布的源码，完成上面的构建和测试后执行：

```powershell
./packaging/portable.ps1 -Executable build/Moxu.exe -Publish
```

脚本按项目版本生成 `dist/Moxu-<版本>-win64.zip`。打包程序通过启动和 SQLite 自检后，脚本更新固定下载包 `downloads/Moxu-win64.zip` 及 README 的两处版本号。`-Publish` 将这两个文件一起提交，并把当前提交推送至 `origin/main`，已有下载链接可继续使用。

本地试包时省略 `-Publish` 即可。要重复打包同一版本，可用 `-Destination` 指定新的输出目录。

完整方案见 [小说辅助系统设计书](docs/设计书.md)，包含书籍欢迎页、正文编辑器、可自定义的插入模板、数据与历史模型、备份恢复和分阶段验收标准。

中文错别字检查与离线模型插件的规划见 [AI写作辅助可行性调查](docs/AI写作辅助可行性调查.md)。当前自动化测试使用本机模拟接口验证请求内容和正文采纳流程。

本项目以离线使用为默认方式。Windows 便携包携带桌面程序的运行依赖。

插件安装前须展示最低配置、推荐配置与本机检测结果；硬性要求不满足时阻止安装。运行时重检可用内存并限制AI资源占用，优先保护正文保存。具体最低配置须按插件版本实测后公布。
